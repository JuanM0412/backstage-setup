# AWS deployment

This directory provisions the AWS resources for Backstage:

- VPC with public and private subnets
- Private RDS PostgreSQL
- EKS managed node group
- ECR repository
- AWS resources for deployment through an externally managed IAM user

Terraform state is stored in an S3 backend. Create the state bucket before
running Terraform and enable bucket versioning and encryption. The bucket must
be private and should have a unique name.

For the initial bootstrap, copy the variables example, review it, and run
Terraform locally from this directory:

```bash
cp terraform.tfvars.example terraform.tfvars
terraform init \
  -backend-config="bucket=YOUR_TF_STATE_BUCKET" \
  -backend-config="key=backstage/terraform.tfstate" \
  -backend-config="region=us-east-2" \
  -backend-config="encrypt=true"
terraform fmt -check -recursive
terraform plan
terraform apply
```

After the first apply, use the `AWS Infrastructure` workflow for subsequent
plans and applies. Configure the `TF_STATE_BUCKET` repository variable and the
AWS IAM user credentials described below.

The infrastructure workflow runs `terraform apply` automatically for matching
pushes. A manual dispatch with `apply=true` also applies the infrastructure;
manual dispatches with `apply=false` run only `terraform plan`.

The RDS endpoint is private and is reachable from EKS nodes only. Do not make
the RDS instance publicly accessible.

## Required GitHub configuration

Create these GitHub secrets in the `aws-infrastructure` environment and in the
`backstage-production` environment:

- `AWS_ACCESS_KEY_ID`: access key for the IAM user
- `AWS_SECRET_ACCESS_KEY`: secret access key for the IAM user
- `AWS_SESSION_TOKEN`: optional, only for temporary STS credentials

The IAM user must have permissions for the actions performed by the respective
pipeline. Do not commit these values or place them in `terraform.tfvars`.

The Kubernetes deployment also requires:

- `BACKSTAGE_DATABASE_URL`: a PostgreSQL connection URI for the RDS database

The URI must use the RDS endpoint from the `rds_endpoint` output and the
password generated by the RDS module. Store the complete value only as a
GitHub secret.

The EKS cluster must also have the AWS Load Balancer Controller installed
before applying `deploy/k8s/ingress.yaml`. The ingress
uses the `alb` ingress class and creates an internet-facing ALB.

The `Deploy Backstage to Kubernetes` workflow builds and publishes the image
and updates only Kubernetes resources. It does not run Terraform.

The pipelines authenticate directly as the IAM user; they do not use GitHub
OIDC or `role-to-assume`. Terraform does not create the IAM user, access keys,
or GitHub OIDC provider. Manage those credentials and their permissions outside
this repository.
